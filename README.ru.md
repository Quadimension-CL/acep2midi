# acep2midi

Конвертер проектов ACE Studio (`.acep`) в стандартный MIDI. **Без лицензионного кода, без сети, без сторонних зависимостей.**

Два способа использования: пакетная конвертация из командной строки или локальный веб-интерфейс с перетаскиванием файлов.

[English](README.md) · [简体中文](README.zh-CN.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

---

## Возможности

- **Полностью офлайн** — всё выполняется на вашей машине, файлы никуда не отправляются.
- **Ноль зависимостей** — только стандартная библиотека Python.
- **Два типа контейнеров** — новый ACE Studio 1.9+ (zstd + base64) и старый zip-формат.
- **Текст песни сохраняется** — слоги записываются в мета-события MIDI `Lyric`.
- **MIDI format 1** — по одной дорожке на вокальный трек, с темпом, размером и названиями дорожек.
- **Библиотечный API** — можно импортировать в собственные скрипты.

## Требования

- Python 3.9 или новее (рекомендуется 3.14+ — встроенный декодер zstd)
- Для zstd-проектов на старых версиях Python: установите `zstandard` или `pyzstd`, либо обеспечьте наличие команды `zstd` в `PATH`

## Командная строка

```bash
# Конвертировать один файл (рядом появится song.mid)
python3 acep2midi.py song.acep

# Указать выходной путь и переопределить BPM
python3 acep2midi.py song.acep -o out.mid --bpm 96

# Только показать результат разбора, без записи файла
python3 acep2midi.py song.acep --inspect

# Пакетная конвертация
for f in *.acep; do python3 acep2midi.py "$f"; done

# Встроенный самотест
python3 acep2midi.py --selftest
```

Все параметры:

| Параметр | Описание |
| --- | --- |
| `-o, --output PATH` | Путь к выходному `.mid` (по умолчанию — как у входного файла) |
| `--bpm BPM` | Переопределить темп, сохранённый в проекте |
| `--ppq N` | Переопределить автоматически определённый PPQ (тиков на четверть) |
| `--title TEXT` | Заголовок, записываемый в MIDI |
| `--no-lyrics` | Не записывать мета-события с текстом |
| `--skip-muted` | Пропустить приглушённые дорожки |
| `--inspect` | Только вывести результат разбора |
| `--selftest` | Запустить встроенные тесты |

Пример вывода `--inspect`:

```
File      samples/demo-realistic.acep
Container zip
Documents 3
BPM       112
PPQ       480
Time sig  4/4
Duration  about 2.1 s (0.04 min)
Tracks    3 (7 notes)

  1. Lead                           3 notes  range 69–76     0.0s →    2.1s
  2. Harmony                        2 notes  range 57–60     0.0s →    2.1s
  3. Drum                           2 notes  range 36–38     0.0s →    0.4s
```

> По умолчанию CLI выводит текст на английском. `ACE_LANG=zh` включает китайский, `ACE_LANG=en` принудительно включает английский.

## Веб-интерфейс

```bash
python3 server.py
```

Откройте <http://127.0.0.1:8850/> и перетащите `.acep` в окно. Можно переопределить BPM и
задать имя выходного файла; после конвертации скачивается `.mid`, а также показываются
число дорожек, число нот, длительность и статистика по каждой дорожке.

Интерфейс автоматически подстраивается под язык браузера (китайский/английский);
можно зафиксировать его через `?lang=en` или `?lang=zh`.

Порт можно изменить переменной окружения:

```bash
ACE_PORT=9000 python3 server.py
```

## Использование как библиотеки

```python
from acep2midi import load_acep, project_to_midi

project = load_acep("song.acep")
print(project.bpm, project.ppq, len(project.tracks), project.note_count)

midi_bytes = project_to_midi(project, title="My Song")
open("out.mid", "wb").write(midi_bytes)
```

Основные объекты:

- `Project` — `tracks`, `bpm`, `ppq`, `time_signature`, `note_count`, `duration_ticks`
- `Track` — `name`, `notes`, `muted`, `kind`
- `Note` — `start`, `dur`, `pitch`, `vel`, `lyric` (время в тиках)
- Все ошибки — `AcepError`

## Как разбирается `.acep`

Обе схемы контейнеров обрабатываются одной логикой:

| Версия | Структура |
| --- | --- |
| ACE Studio 1.9+ (например, 1.9.6) | Внешний JSON; поле `content` — данные, **сжатые zstd и закодированные base64** |
| Старые / сторонние варианты | Zip-контейнер с одним или несколькими JSON-документами |

Этапы разбора:

1. **Распаковка** — zstd через стандартный модуль `compression.zstd`, `zstandard`, `pyzstd` или системную команду `zstd` (что найдётся первым); поддерживаются также gzip/zlib. Иначе файл считается zip или «сырым» JSON. Кодировки перебираются по порядку: UTF-8 BOM, UTF-8, UTF-16.
2. **Поиск нот** — все JSON-документы обходятся рекурсивно; массив объектов считается списком нот, если не менее 60% выборки содержит и поле высоты, и поле времени начала. Найдя такой массив, обход внутрь него прекращается, а имя дорожки берётся из родительского объекта (`name` / `trackName` / `channelName` / `title`).
3. **Нормализация имён полей** — при сравнении игнорируются регистр, подчёркивания и дефисы; для каждого понятия поддерживается несколько кандидатов:

   | Значение | Поля-кандидаты |
   | --- | --- |
   | Высота | `pitch` `midiNote` `noteNumber` `key` `note` |
   | Начало | `start` `startTick` `startTime` `onset` `tick` `time` `offset` `pos` |
   | Длительность | `duration` `dur` `length` `len` `noteLength` |
   | Сила нажатия | `velocity` `vel` `volume` `gain` `intensity` `loudness` |
   | Текст | `lyric` `lyrics` `word` `syllable` `text` |
   | BPM | `bpm` `tempo` `beatsPerMinute` |
   | PPQ | `ppq` `ticksPerBeat` `ticksPerQuarter` `resolution` `division` |

4. **Высота** — принимаются числа (`60`) и названия нот (`C4`, `F#3`, `Bb5`).
5. **Сила нажатия** — целые 0–127 и нормализованные 0–1.
6. **Единица времени** — приоритет у `timeUnit` паттерна (`tick` / `sec`). Иначе определяется по данным: дробные начала/длительности при небольшом масштабе либо все начала меньше 64 означают секунды и переводятся через `PPQ × BPM / 60`; остальное считается тиками.
7. **PPQ** — файлы проектов обычно не хранят разрешение, поэтому оно выводится из сетки тиков: НОД всех начал, длительностей и соседних интервалов даёт шаг сетки, затем проверяются варианты `шаг × 2/× 4/× 8/× 16` и выбирается тот, где больше нот попадает на тактовые линии и доли. Для проектов ACE 1.9.6 измеренное значение — **480** (совпадает с их экспортом в VSQX).
8. **Вывод** — MIDI format 1. Дорожка 0 содержит заголовок, темп и размер; для каждой нотной дорожки создаётся свой MTrk, текст песни пишется в мета-события `Lyric`, канал 10 (перкуссия) пропускается.

Если в какой-то версии используются совсем другие имена полей, достаточно добавить их в кортежи
`PITCH_KEYS` / `START_KEYS` / `DUR_KEYS` / `VEL_KEYS` / `LYRIC_KEYS` в начале `acep2midi.py` —
остальная логика менять не нужно.

### Проверено на реальном проекте

Реальный проект ACE Studio 1.9.6 (четыре вокальные дорожки) сверен с экспортом VSQX из той же папки:

- Извлечены все 4 дорожки, 597 нот (включая 47 нот-продолжений) и 464 слога.
- Послоговое сравнение с VSQX показало постоянное смещение позиций (40200 тиков) и совпадающие длительности — значит, ось времени разбирается верно.
- Определённые PPQ 480 и BPM 190 совпадают с `<resolution>480</resolution>` и `<tempo>190</tempo>` в VSQX.

## Ограничения

- **Только ноты и текст.** Pitch bend, вибрато, дыхание, энергия и другие автоматизации
  (раздел `parameters` проекта) в MIDI не записываются; всем дорожкам назначается фортепиано
  по умолчанию — инструмент можно переназначить в DAW.
- **Аудиодорожки пропускаются.** Дорожки `type: "audio"` ссылаются на внешний WAV; самого
  аудио в файле проекта нет.
- **Это эвристика, а не официальный формат.** Если реальный проект разбирается неверно,
  сначала запустите `--inspect`, чтобы увидеть найденные дорожки и ноты, затем дополните
  списки полей-кандидатов выше.
- **PPQ определяется приблизительно.** В редких случаях (все ноты строго на долях) возможна
  ошибка — используйте `--ppq`, чтобы задать значение вручную.
- Выходной файл — MIDI format 1 (многодорожечный).
